# 조회한 번호 저장 기능 설계

날짜: 2026-08-23
대상: `src/LottoHistoryChecker.jsx` (서버 없는 정적 GitHub Pages 앱)

## 목적

대조한 번호 조합을 브라우저에 보관해두고, 나중에 다시 불러와 대조할 수 있게 한다.
저장 시점의 대조 결과 요약도 함께 남겨 목록에서 바로 성적을 확인한다.

## 저장 형식

`localStorage` 키 `lc.saved.v1` 에 배열로 저장한다. 항목:

```json
{
  "id": "3-14-22-30-41-45",
  "numbers": [3, 14, 22, 30, 41, 45],
  "savedAt": "2026-08-23T05:12:00.000Z",
  "summary": {
    "counts": { "1": 0, "2": 0, "3": 2, "4": 11, "5": 140 },
    "best": 5,
    "bestCount": 2,
    "total": 1238,
    "source": "lotto_history.json",
    "isSample": false
  }
}
```

- `id` 는 정렬된 번호를 `-` 로 이은 문자열이라 같은 조합은 항상 같은 id 가 된다.
- 같은 조합을 다시 저장하면 항목을 새로 만들지 않고 `savedAt` 과 `summary` 를 갱신한다.
- 최대 100개. 넘으면 `savedAt` 이 가장 오래된 항목부터 버린다.
- 읽기/쓰기는 모두 `try/catch`. 사파리 프라이빗 모드나 용량 초과에서 앱이 죽지 않아야 한다.
- 저장된 값이 손상됐거나 형식이 맞지 않으면 조용히 빈 목록으로 취급하고, 사용자가 저장하기 전까지 덮어쓰지 않는다.

## 코드 구조

순수 함수는 `src/savedNumbers.js` 로 분리한다. React 에 의존하지 않는다.

- `keyOf(numbers)` — 정렬 후 id 문자열
- `loadSaved()` — localStorage 읽기, 손상 시 `[]`
- `persist(list)` — localStorage 쓰기, 실패 시 `false`
- `upsert(list, entry)` — 중복 병합 + 상한 처리, 새 배열 반환
- `removeAt(list, id)` — 삭제
- `mergeImported(list, incoming)` — 가져온 목록 병합(같은 id 는 최신 `savedAt` 우선)
- `toExport(list)` / `parseImport(text)` — JSON 내보내기/가져오기

컴포넌트는 `saved` 상태 하나와 위 함수들만 쓴다.

## UI (승인안 A)

- **저장 버튼**: 결과 영수증 머리말 옆. 아직 저장 안 됐으면 `이 번호 저장`, 저장돼 있으면 `저장됨 ✓` 이며 다시 누르면 저장 해제. 대조 결과가 있을 때만 보인다(요약이 있어야 저장 가치가 있다).
- **보관함**: 왼쪽 열, 마킹 용지 아래의 별도 `.lc-paper` 카드. 항목마다
  - 번호 6개(작은 볼)
  - 저장일
  - `3등 2회 · 최고 5개 일치 · 1,238회 기준` 형태의 한 줄 요약 (샘플로 낸 결과면 `⚠ 샘플` 을 덧붙인다)
  - `불러오기`(→ `picked` 로 복원, 결과 초기화) / `삭제`
  - 비어 있으면 안내 문구만 보여준다.
- **하단**: `내보내기` / `가져오기` 작은 버튼. 가져오기는 기존 목록에 병합한다.

## 범위 밖

- 서버 동기화, 계정, 공유 링크
- 저장 항목의 자동 재대조 (회차가 갱신돼도 요약은 저장 시점 기준이며, 그래서 `1,238회 기준` 을 함께 적는다)
- 자동화 테스트 (사용자 결정으로 이번 범위에서 제외)

# 추가: 추천 조합 기능 (2026-08-23)

## 목적

"1·2·3등 당첨 이력이 없으면서 4등 이력이 많은" 번호 조합을 찾아 5개씩 추천한다.

## 알고리즘

조합마다 전 회차를 대조하면 8,145,060 × 1,238 ≈ 100억 번이라 감당이 안 된다.
회차별 부분집합 빈도표를 미리 만들어 조합 하나를 표 조회 15번으로 판정한다.

- `t4[rank]` — 4개 부분집합이 등장한 회차 수 (회차당 C(6,4)=15개 등록)
- `t5[rank]` — 5개 부분집합이 등장한 회차 수 (회차당 C(6,5)=6개 등록)
- rank 는 combinatorial number system (`ΣC(x_i, i+1)`) 으로 매긴 고유 번호

조합 S 에 대해 `a5 = Σ C(m,5)`, `a4 = Σ C(m,4)` (m = 회차와 겹친 개수) 이므로

- `a5 == 0` ⟺ 5개 이상 맞은 회차가 없음 ⟺ **1·2·3등 이력 없음**
- 그때 `a4` 가 곧 4등 횟수

6중 루프에서 앞 5개가 정해진 시점의 값을 미리 더해두어, 가장 안쪽 루프는 표 조회
15번만 한다. 실측 **247ms** (Node, 1,238회차 기준).

## 검산

무작위 3,000조합과 실제 50회차 번호에 대해 직접 대조 결과와 비교해 불일치 0건.
브라우저에서도 추천된 조합을 «대조하기» 에 넣어 1·2·3등 0회 / 4등 횟수 일치를 확인.

## 결과 (1,238회차 기준)

- 1~3등 이력이 없는 조합: 7,858,956 / 8,145,060 (96.49%)
- 4등 이력 분포: 0회 142만 · 1회 246만 · ... · 10회 54개 · 11회 12개 · **12회 2개**

## UI

마킹 용지와 보관함 사이에 «추천 조합» 종이 카드. 첫 «추천 조합 뽑기» 에서 웹 워커로
탐색하고(진행률 표시), 이후 «다시 뽑기» 는 상위 500개 풀에서 즉시 5조합을 다시 뽑는다.
각 줄에 «용지에 넣기» 로 마킹 용지에 바로 반영. 각주에 통계와 함께
"추첨은 매 회차 독립이라 과거 이력이 당첨 확률을 높이지 않는다"를 명시한다.
워커를 못 쓰는 환경에서는 같은 코드를 메인 스레드에서 실행한다.
